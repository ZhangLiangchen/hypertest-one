# Cloud 测试任务使用流程

本指南描述 [ADR-038](architecture/ADR-038_TASK_FOCUSED_CLOUD_INPUTS.md) 的任务工作流。实际可用性取决于已部署版本；源码、自测、部署及用户验收分别记录。

1. 在项目详情点击“编辑”，维护被测对象仓库和测试框架仓库。两个角色可以使用同一仓库。Cloud 不再有单独的项目资源页。
2. 创建 Cloud 测试任务，填写名称、测试目标、MR/PR 地址、需求及基本流程。MR 所在仓库须属于 Project 的 SUT 仓库或其下级范围；Project 使用 GitLab group 地址时，以 MR 定位该组下的实际仓库。在目标或流程 prompt 中明确要在哪个测试环境测试、执行内容与限制；不要粘贴凭据。MR/PR 地址帮助 Agent 阅读改动，不代表该改动已部署。
3. 如需固定特定检出来源，展开源码设置填写 SUT 和测试框架版本；省略时使用仓库 HEAD。保存草稿后解析版本、核对实际 SHA，再下发任务。保存草稿和解析来源均不会启动 Agent 测试。
4. 在任务详情跟踪接取、执行进度和待回答问题，查看归档的分析、用例、代码、原始报告及结果。任务完成和测试通过分别显示。
5. 需要复测时，在原任务明确本次范围与授权，创建独立 Attempt；原报告和结果仍可追溯。原操作结果未知时先按原身份核对，不能靠复测重发未知动作。

项目仓库修改不回写已冻结任务。编辑草稿会采用 Project 当前仓库地址并要求重新解析。MR/PR 地址与实际检出版本分别记录；被测环境的部署由该项目自己的 CI 和工具负责，HyperTest 不设置预期部署版本或管理测试环境。

旧资源页链接现在显示任务列表；旧任务快照中可能仍含历史环境信息，仅解释当时输入。当前任务的实际环境、版本和结果以 Agent/框架报告的来源及观察范围为准。
