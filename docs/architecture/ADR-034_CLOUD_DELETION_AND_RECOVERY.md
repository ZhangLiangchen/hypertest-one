# ADR-034：Cloud 列表删除与执行收尾分离

日期：2026-11-03（Asia/Singapore）。状态：Accepted；实现、部署与用户验收分别记录。

## 问题

Cloud 删除创建墓碑并隐藏目录记录，不清除任务历史。然而旧准入要求先确认所有外部操作结束，导致已请求取消的待恢复任务在外部结果长期 UNKNOWN 时无法移出列表。直接放宽状态限制又会被墓碑后的统一禁写规则阻断后续对账。

## 决定

- 保留草稿和已收尾任务的现有删除条件；额外允许最新 Attempt 已处于 `RECOVERY_REQUIRED`、已记录取消请求且旧 writer 已 fence 的任务移出列表。未决输入解析仍阻止删除；活动任务不能通过删除隐式取消。
- 对这一待恢复分支，未知外部操作、未收口容器或委派不阻止列表删除，但其身份、状态、结果、原件、原 key、checkpoint 和预算继续保留。删除仅推进 Task version 并追加不可变墓碑及接受快照，不标记已停止、已对账或终态。
- 删除后仍可通过原任务链接读取历史和当前恢复状态。仅在原有鉴权、当前版本、最新 Attempt 及 fence 检查下允许人工收尾、原动作观察授权、原容器恢复确认和停止/未启动观察；其原有阻断条件继续适用。禁止新下发、续接、普通 Worker 写入和其他管理修改。
- 数据库仅允许已删除的待恢复 Task 逐版本保持恢复或收尾为 FAILED/CANCELLED；输入、结果及执行身份保持冻结。墓碑与删除时的固定快照不因后续恢复更新。
- 页面明确说明“移出列表”与“待对账”可以同时成立，不能要求用户为清理列表作不真实的停止声明。

本决定取代领域 §51 和 TMP §46 中与上述待恢复删除及受限恢复例外冲突的限制。不改变 UNKNOWN 原 key 对账、外部操作不自动重发或结果真实性规则，也不授权硬删除业务记录。
