# ADR-041：Cloud 是 Harness 的任务与对话外壳

**状态：Accepted。日期：2026-11-04。决定者：项目负责人。**

## 决定

云端测试把本地 Harness 的测试流程搬到执行节点。HyperTest 负责项目、任务入口、会话连接、消息和产物持久化；DeepSeek Harness 负责计划、工具、团队、执行权限、审批和自身会话队列。平台不另建测试阶段控制、审批、人工接管或停止对账流程。

任务页以 Agent 对话和报告/附件为主。对话是持久化的异步消息，不要求用户维持在线连接。发送接口只保存文字与原 key；无论 Worker 是否在线、是否正在恢复或此前消息投递未确认，新的不同消息均可保存。Worker 在领取循环中发现已保存的 QUEUED 消息，再连接同一 Attempt 的原 Harness 会话并投递；不依赖用户再次发送或点击重连。恢复只调用 SDK resume，不生成默认 continuation，不重发原任务 prompt。原生提问继续通过 Harness 回调转发，包括 Harness 已支持的 approval intent；原问题与答案透传，不改变平台 grant，不接管 SDK 独立 approval answerer。

Worker 核对原工作区与 session，SDK 负责实际会话写锁和恢复。缺失、占用或连接失败作为具体执行问题记录；临时故障由 Worker 退避处理，永久身份或授权错误不自动重试。不让用户填写进程停止、外部动作对账、身份指纹或 OPERATOR_ADOPTED 声明。模型、工具权限和审批沿用 Harness 配置，不能由平台表单代办或扩大。

## 保留的传输职责

项目访问控制、消息归属、单次投递、原 key 查询、领取 lease/generation、存储格式和秘密检查属于通信/存储职责。它们不决定测试步骤或业务动作。发送接口的 generation 由服务端分配，不是用户输入；只有尚未尝试投递的 QUEUED 消息可在重连时调整投递 generation。DELIVERING/UNKNOWN 消息不得改身份或重发，原 SDK 回执可补齐确认；其未决状态阻止后续投递但不阻止保存新的不同消息，也不影响其他会话。浏览器对保存失答自动查询原 key，不要求用户核对投递或重连；同一未决正文不重复提交。普通断连保留未投递消息，显式取消才取消这些消息。

未冻结、明确未提交的格式、内容和产物文件错误只拒绝对应归档贡献；Worker 写入固定修正反馈并通过 SDK 向 Agent 投递一次，Agent 对话继续。反馈本身的发送身份持久化，SENT/UNKNOWN 不重发，晚到回执可补确认。权限、路径越界、已冻结归档及不确定的平台提交继续保留原拒绝与原 key 恢复边界，不能伪装为可替换的新贡献。

Native Cloud 的报告归档不要求 ANALYSIS/DESIGN/CASE/IMPLEMENTATION 阶段齐全、平台委派终态或外部业务对账审批。最终报告须属于当前 Attempt，结果字段与提交的报告一致，未确认的平台归档请求仍按原 key 处理。结构化 Run 和其他测试资产可选；平台保存 Harness 报告的结论，不从 idle 或一句回复生成 PASS，不制造 Run，不升级为独立验证 Evidence/Gate，也不改写既有观察。任务正式结束后本轮对话只读。

## 取舍和替代范围

采用 Harness 原生流程，删除重复的平台流程控制；不采用在 HyperTest 再造一套人工审批后继续执行的方案。用户只操作普通消息；执行状态、消息处理进度和归档失败分别呈现，不能用平台声明冒充 Harness 或外部系统的事实。

本决定替代 ADR-039 的人工接管/停止对账续接要求，以及领域 §51、TMP §46、技术架构 §45 中应用到当前宿主 Native Cloud 的阶段/运行记录/委派/外部业务完成 gate。旧容器、独立 Native、Local 和 Memory 的合同不因此重写；历史记录保留，旧 RESUME_ATTEMPT 新写停止，已接受原回执仍可读。本轮不删除业务数据、不触发指定业务任务验收。
