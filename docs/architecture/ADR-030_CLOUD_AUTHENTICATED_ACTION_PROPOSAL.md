# ADR-030 草案：Cloud 测试框架的受控认证与外部写入

**状态：提案，未实现、未准入、未部署。** 日期：2026-10-29（Asia/Singapore）。本稿不改变现行规范或赋予网络和写入能力。实现时须按实际合同同步领域模型、测试任务协议和技术架构；[ADR-025](ADR-025_CLOUD_CONTROLLED_HTTPS_READS.md) 的公开只读 profile 保持原义。

## 目标与已知约束

Cloud Agent 调用项目既有测试框架；框架需要访问认证服务、签名请求或发起有副作用的 HTTPS 操作时，平台提供受控传输与凭据边界，不定义项目的测试用例、订单字段、签名算法、断言或链上业务规则。不能将 OAuth 密码、API key、签名私钥、Gateway HMAC key、Bearer token、平台 writer token 或数据库凭据暴露给 Agent。不得把本机已限定为 Local-only 的秘密入口复制到 Cloud，也不得绕过 XBlock SSH、内网和源地址限制。

现有 `HTTPS_CONTROLLED_API_V1` 只接受固定无认证 GET/HEAD；其 `OBSERVED` 意味着 HTTP 响应已观察，并在原有只读场景解除该操作的未决状态。这个语义不能用于异步写操作：HTTP 200/202 可能只表示受理，订单和链上交易仍待完成。新增能力必须使用独立 profile 和账本，保持 V1 不变。

## 受控动作与请求原件

1. 先为 Project 的受控环境固定服务 origin、允许的精确方法和路径、每类动作的权限、期限、请求/响应大小和次数上限、允许的目标与必要的框架版本；`environment:write`、对应 Project grant 与独立的凭据使用授权均须明确。读取权限或共享 Project 不自动授予写入。允许的字段和取值范围由经过审核的项目适配合同声明，不能靠 Agent 文本扩大；缺少适配合同即拒绝。
2. 每个实际动作独立持有稳定原 operation key、CloudTask/Attempt 与业务关联身份。调用方必须在执行前生成并保留 client reference；该引用是否被服务端支持、可查询或具备幂等性，需要目标契约证据，不能从名字或查询不到记录推断。目标账户、资产、数量及授权上限应在授权中明确；不由平台推算业务参数或自动生成替代操作。
3. 由可信侧生成实际将要发送的请求体**原始字节**并做有界检查；固定 body 长度及 SHA-256，不重新序列化 JSON 作为签名、摘要或发送输入。签名和认证在已冻结的请求与目标边界中完成；传输模块发送的 body 必须与已固定的字节逐字一致。请求头中的认证材料不写入普通账本、审计或日志。
4. 原始请求可能含签名或敏感业务数据，须置于当前 Attempt 的受限私有原件存储，记录精确内容身份与访问控制；不得将密码、token、密钥或未扫描的正文放入公共任务快照。持久化前执行既有项目秘密检查；不能以普通摘要、Agent 断言或 `SecretStr` 替代凭据隔离。持久化哪些私有签名原件及其加密/保留策略，须在确定具体 signer 前实现并核验。
5. 在任何外部发送之前，服务端按 Project / Task / Attempt、当前授权、lease/generation、冻结配置、原 key 与请求摘要原子持久化 `SENT` 并提交。只有新建且仍具有有效当前权限的原操作可获得一次发送许可；并发同 key 只能得到同一原记录，内容冲突拒绝。`SENT` 提交后即使发送前崩溃，也不能从无回执推定未发送或自动重发。

实现阶段需定义用户授权的请求策略与 framework 适配如何生成该最终原文。框架可能先按业务字段做 RSA 签名，再按最终 HTTP body 计算 Gateway HMAC；不能在 broker 里重排 body 后沿用旧签名，也不能把任意签名能力暴露给 Agent。调用项目固定 signer 的可信实现、可审计签名边界与执行环境须明确；尚不能把未经审核的可写框架源码作为有权读取密钥的宿主插件。若不能确保最终原文字节与实际发送一致，应拒绝发送。

## 凭据与网络

凭据按用途分别标识、版本化、绑定获准 Project、target、操作与有效期；例如 member API key、OAuth 身份、请求签名密钥及可选 Gateway HMAC key 不因同一项目而互相替代。真实凭据只由受限可信侧按当前 WorkGrant 和操作取得；模型身份、Git 身份、Local 配置与环境身份各自独立。OAuth 登录、token 有效期及敏感输出不得进入 Agent、测试报告或普通日志。

Agent 只能通过限域私有通道提出已授权的操作，不能指定 URL、网络目的地、任意 header、凭据引用或签名器。host broker 复用对已批准 origin、公开地址 pin、TLS hostname、无重定向、无环境代理、无自动重试和有限截止/大小的保障；是否允许某个新目标，须有独立授权和网络路由，不因本提案扩大。认证请求与无副作用报价是否可安全重试应由明确的 provider 合同决定，不从 HTTP 方法本身推断；具有未知副作用的请求沿单次发送与原身份对账规则。

## 传输观察、业务终态与恢复

| 状态或观察 | 意义与约束 |
| --- | --- |
| `SENT` | 原意图已提交且最多有一次发送许可，不证明实际发送或未发送。 |
| `HTTP_OBSERVED` | 已获得并保存与原请求匹配的有界 HTTP 响应；状态码/响应不自动表示订单、链上交易或测试 PASS。 |
| `UNKNOWN` | 任一提交/传输/收尾结果不明；保留原 key、摘要、凭据引用与预算 hold。 |
| `BUSINESS_TERMINAL` | 仅由对应 provider 的受信只读观察机制基于原业务 ID、原始材料、实际状态和观察时间建立；不存在通用的“HTTP 200 即终态”规则。 |

这些是提案语义，不是已存在的 enum 或 API。不可变历史分别保留 HTTP 与业务观察；同一原操作出现冲突观察不得覆盖旧记录。查询不到订单、关闭本地连接、取消请求被接受或容器退出都不能证明远端未执行或已结束。UNKNOWN 恢复只查询原 key / 原 provider ID；不能变更 key、替换 order ID 或重发 POST。业务终态尚未由可信适配器观察时，任务完成、预算结算、人工收尾及新 Attempt 必须继续被阻止，保持 `RECOVERY_REQUIRED` / HELD。

恢复者须重新获得当前 Project、Task、Attempt 与专门的只读恢复授权；新的 fenced generation 可以只读查询旧记录，但不能借新 lease 变更原操作身份或再次发送。失权后的普通结果写入拒绝；对 UNKNOWN 的有限安全观察不能制造业务终态。管理员声明本身也不能消除 UNKNOWN。

## 真正接入点与待完成输入

- `api/cloud_schemas.py`、资源修订和 Cloud Task 输入须增加独立的 typed 授权、凭据绑定和冻结字段；旧输入序列化及其 digest 不变。新增 capability 默认关闭，不能把 V1 的 `supported` 或 `environment:read` 当成写许可。
- `application/cloud_tasks.py` 及数据库需新增不可变的写 intent 与观察，按原聚合锁和复合归属约束串行化；将业务未终态纳入 `cloud_ssh.ensure_remote_closed` 的统一收尾检查。旧 `cloud_http_operations` 和其结果不得复用于异步写入。
- 新 Worker broker 在发送前再次检查当前 grant、租约、期限、目标、原件和累计预算；它只发送受控原始字节，不给 Agent 平台 writer 或通用网络。凭据物化、原件安全保存、逐操作回执、停止与 broker drain 均需完整实现。
- 项目框架需要显式接入该 transport/签名边界；普通 `requests.Session`、OAuth 请求或 RSA 私钥不会因存在 UDS 自动接通。项目现有代码与运行依赖须固定到实际版本，不在 HyperTest 重建其业务 DTO。
- 每个 provider 的关联查询、真实终态、权限和拒绝语义需要来自其源码/接口及实际环境的证据；target、credential 类型、来源、到账地址、token 精度与真实 SUT 部署身份须由目标环境确认。本次已知 XBlock 订单查询路径不证明 DEX 覆盖或链上终态。

实现前至少针对目标版本提供受限可信 signer/序列化方式、精确授权与凭据用途、可核验的原业务 ID 查询和终态解释。若缺少其中任意一项，不能开放发送；可保留为待输入或继续只读检查。

## 必要验证

使用专用测试数据库和合成凭据/目标，对授权与拒绝、原始字节摘要、并发同 key、提交前后失答、NOT_FOUND、不重发、凭据不进入快照/日志、不同 Project/Attempt 与旧 generation 拒绝、HTTP 响应不能解除业务未决、业务观察冲突和取消/fence 后收尾做定向回归。受控 TLS、认证和项目 signer 的真实路径须另行测试；这些回归不代表真实 staging 执行、链上结果或用户验收。目标本次的 2/4/5/7 USDT 是四次不同动作；最终是否发送和结果均由各自原订单及实际观察记录，不能合并或自动重试。
