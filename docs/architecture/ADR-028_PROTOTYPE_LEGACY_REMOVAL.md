# ADR-028：快速原型期移除冲突的旧实现与数据

日期：2026-10-28（Asia/Singapore）。状态：**已采用**；由项目负责人决定。本文确立后续开发规则，本次文档变更不执行代码移除、数据清理或部署。

## 背景

HyperTest One 仍处于快速原型阶段。随着产品设计和实现演进，继续维护相互不一致的旧入口、数据模型和行为会增加实现与维护成本，也容易误导使用者。此前多份规范将旧实现和历史数据保留作为默认要求；该要求在新旧实现冲突时不再适用。

## 决定

1. 快速原型阶段，以已确定的新产品合同和实现为准。新旧实现不一致或旧实现已被替代时，不要求保留旧 API、页面入口、旧客户端、适配层、数据模型或兼容逻辑；直接移除冲突的旧实现和兼容入口。
2. 与被移除旧实现对应的旧数据可直接删除，包括旧任务及其相关记录，无需为了兼容迁移到新模型、保留旧读取入口或逐次再请求用户批准。例如，任务创建改为新方案时，属于被替代实现的旧任务数据和兼容入口不要求保留。此例说明规则，不表示本次已识别或删除具体任务。
3. 每次实施应依据当前产品合同和实际代码、schema 明确新实现、被替代的旧实现、删除的数据及依赖范围，按该范围实施变更；不以“旧”字样或历史日期代替判断。允许必要的破坏性迁移，不要求为旧数据设计兼容或恢复流程，也不把冷备、恢复演练和额外审批设为默认前提。
4. 删除限于实际被替代实现及其相关数据；新实现的数据、无关项目/任务、凭据、访问限制、其他插件和无关服务不因该决定而删除或改动。若数据跨新旧实现共享，应先明确归属及影响，避免误删新实现依赖。
5. 清除后的历史和旧链接可能无法访问；不得伪称已迁移、保留或完成业务验收，也不能把旧报告伪造为新模型事实。源代码、部署与数据清理各自记录实际结果及范围。
6. 未决外部操作不能因退出旧实现被自动重发、换 key 或推定成功/失败；如仍保留原 key 和恢复路径，按其现行合同对账。旧账本被纳入明确的清理范围时，其恢复能力可能随之消失，须如实记录，不得通过重放制造确定性。

本决定取代 ADR-027 及更早 ADR、基础文档、运维和 Agent 指引中对**被替代旧实现**强制保留兼容入口、旧数据和历史的要求；未被替代的现行合同和授权、身份隔离、证据真实性仍然有效。历史交付记录只说明当时的事实，不构成继续保留旧实现或旧数据的要求。任务具体新旧身份与清理范围由具体变更确定，不以本 ADR 宣称所有已有旧 profile 已移除。

## 考虑的方案与后果

- 保留旧实现和历史兼容：既有数据和访问路径可继续使用，但每次变更需要维护多套行为，快速原型成本高，选择不采用为默认方案。
- 采用新实现并删除相应旧实现及数据：降低开发和维护负担，但被删除的旧任务、报告、回执或历史将不可恢复或不可访问；若需要在特定场景保留或迁移，由该场景的明确需求决定。

此决策有效期为项目快速原型阶段。产品进入需要稳定兼容或数据留存的阶段时，应以新的明确决策重新规定迁移与保留策略。
