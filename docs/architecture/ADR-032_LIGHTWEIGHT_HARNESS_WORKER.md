# ADR-032：快速原型期的轻量 Harness Worker

**状态：Accepted；实现、部署和用户验收分别记录。**
**日期：2026-11-02**

## 背景与取舍

HyperTest One 管理测试项目、下发测试任务并记录测试结论；项目既有工具和 Harness 负责实际测试。现阶段只有 DeepSeek Harness 已接入，产品处于快速原型期。当前每次 Cloud Attempt 创建 Docker 容器和由平台配置环境访问的方案增加了开发及使用复杂度，也不能直接使用当前 Mac 的工具、登录和网络。

**项目笔记：本阶段选择轻量 Worker 是为了快速原型，并不意味着放弃项目资源隔离。** 从项目资源隔离角度，未来目标是全盘容器化；何时采用、隔离边界与迁移方案须结合实际部署重新设计和验证。当前宿主进程继承执行用户的系统权限，不能将其说成项目间强隔离。

## 决定

- HyperTest 服务端负责项目、任务、结果和必要的状态持久化。
- 轻量 Worker 是可独立分发的进程，负责领取任务、调用 Harness 适配器和回传结果，不实现智能体循环或团队编排。
- DeepSeek 适配器调用官方 SDK；DeepSeek Harness 负责其模型、插件、智能体团队、子智能体和工具。将来接入其他 Harness 时增加适配器，不把其实现纳入控制平面。
- 原型默认不为每个任务创建独立容器。Worker 和 Harness 在执行节点运行：当前 Mac 为宿主机；公司环境可根据实际执行节点选择部署位置。GitHub/GitLab 登录、网络、测试工具和被测环境由执行环境配置；任务表单不把环境连接方式或 HyperTest 托管的仓库凭据作为新流程的必需条件。
- Worker 空闲时通过程序等待或查询任务，不因轮询调用模型；只有实际任务调用 Harness 时才可能产生模型使用。Worker 与服务端的通信应使用独立的受限身份，不向 Harness 或 Agent 传递平台数据库、Operator 或 Worker 凭据。宿主同一用户的进程并非操作系统强隔离，不能声称 Agent 不可能访问该用户可访问的其他资源。
- 保留任务身份、版本、领取权、结果来源和原 key 对账等必要语义；网络失答、进程终止与未观察到的外部操作不能推定未执行，不自动重发或伪造测试结果。SDK idle、正常退出或报告文本不自动证明外部操作停止、测试通过或正式 Evidence。

## 方案比较与影响

DeepSeek 插件可在已常驻 Harness 中承担任务接入，但使交付和生命周期依赖特定 Harness；跨其他 Harness 需分别适配。保留轻量 Worker 便于独立安装、按需启动 Harness 及今后增加适配器。容器化方案更适合强化项目资源隔离，但当前不是每任务准入或默认交付前提。

此决定取代 ADR-031 中新 Cloud 任务必须使用独立容器、独立 SDK profile 快照、仅工作区内测试和由平台管理 Git/环境访问的限制，以及 ADR-019、领域 §51、TMP §46 和技术架构 §45 中与新轻量执行路径冲突的具体部署和运行准入要求；保留其任务身份、报告真实性、未决操作与安全事实语义。历史已冻结任务及其执行记录仍按原 profile 解释；ADR-028 可用于明确范围内的替代与清理。

## 实施状态

本 ADR 是已决定的目标，不能作为已完成实现、已部署或已验收的证据。新 Worker 的宿主安装、认证与通信、任务领取、SDK 适配、结果回传及原 key 恢复应分别实现和验证。现有容器 Worker 的行为在替换部署前仍是运行事实；真实 Harness、凭据、项目测试和用户验收需分别观察。

宿主安装准备工具 `scripts/prepare-macos-cloud-worker.py` 生成指定已推送 Git SHA 的 LaunchAgent 和受限 BFF 配置，`scripts/install-macos-cloud-worker.py` 可安装该 LaunchAgent；它们不配置用户的 Git、SSH、模型身份或 Harness 插件。SDK 的 `sdk` profile 与相应认证需由执行环境提供。LaunchAgent 登录时启动，运行中发生不确定领取或异常后不自动重启；必须核对原领取及租约后再处理，不能重放未知请求。Shell 临时 `export` 不一定属于 launchd 环境；需要在执行服务的真实环境中配置身份，不能假设交互终端的环境变量自动继承。
