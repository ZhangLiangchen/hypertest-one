# ADR-033：原云端任务的独立重试执行快照

**状态：Accepted；实现、部署及用户验收分别记录。**
**日期：2026-11-02**

## 背景

失败是测试过程的一部分。CloudTask 的初次冻结输入和已有 Attempt、动作身份、原始报告需要保持历史含义；同时操作者需要在同一任务中明确指定下一次测试的范围和授权。旧冻结任务可能包含已耗尽的历史预算、旧版受控动作和仅限一次执行的指令。

## 决定

- 原 Task 可追加新的 Attempt。重试须指向该 Task 最新且已终结的 Attempt，由有权操作者分别确认本次测试范围和授权；具体目标、范围、流程、框架入口和授权形成该 Attempt 独立的不可变执行快照及摘要，绑定原 Task、Attempt、版本与来源冻结身份。请求和回执使用原 operation key 与 expected_version，失答按原 key 查询，不自动换 key 重发。
- 新快照引用原 Task 固定仓库 SHA 与配置，不修改原 Task 输入、旧 Attempt、动作身份、报告或原预算及其 HELD 账务。历史 PRD 为上下文，本次明确确认的执行范围、流程与授权约束新工作；原一次性命令不得被当成新授权自动重跑。需要更换源码或资源的情形仍按相应资源合同处理。
- 原 SSH、HTTP、受控动作与容器记录按原身份核对；尚未解决的已知操作或未收口原容器阻止下发。没有响应不等于未执行；禁止自动重发未知操作。新 Attempt 不能继承旧受控动作 broker 或旧预算额度，也不能伪造独立过程停止证明或原结果。
- 新 Attempt 沿用 ADR-032 宿主薄 Worker 的实际执行方式：Harness 继承宿主用户权限，缺少 OS 强隔离；授权确认和 prompt 本身不是强制网络或凭据隔离。旧受控动作账本继续保留和对账，但不能声称由宿主工具直接发起的新外部操作自动进入旧账本或拥有原 broker 的去重保证。新尝试的实际动作和测试结果须由执行环境及项目工具按来源如实记录；平台不自动重放未知动作。
- ADR-031 对旧冻结任务一律不得再次下发的限制，在本独立 Attempt 快照模式下由本决定取代；旧任务本身与旧账务仍按原 profile 解释。先前的复测设计中选择性强隔离及动作 broker 属于未来可选增强，不作为本宿主路径已具备的能力。

## 后果与验证

测试须覆盖旧 Attempt 原件、原动作与原 key、确认缺失和版本冲突、未决操作拒绝、快照不可改写、领取及 Worker 使用同一快照、原 HELD 不结算，以及新 Attempt 结果正确归属。仅在专用测试库和合成目标上执行自动回归；实际业务测试由用户确认范围和授权后自行验收。宿主网络、凭据和其他进程无法由本特性强制隔离，不将 Agent 自报升级为独立执行证据。
