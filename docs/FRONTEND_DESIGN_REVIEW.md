# 前端设计与验收记录

日期：2026-10-18。范围：项目工作台、项目运行列表、测试运行工作台、创建向导、详情抽屉和共享导航。

## 使用路径

项目工作台提供名称、标识和仓库搜索，以及状态筛选。项目内以运行列表比较固定输入与流程状态。运行默认进入概览：先查看正式质量判定和最近后台任务，再进入失败记录、问题发现、执行证据和判定依据。

桌面使用左侧页签索引，窄屏使用可滚动页签及溢出菜单；键盘可用 Home / End 定位首尾页签，Enter 激活。完整测试周期是主操作，规划任务、单独执行、评估质量门禁和运行输入位于“更多操作”。原有 API、请求幂等性、输入限制、生命周期和历史入口保持原有契约。

## 产品语义

- 后台任务完成不代表测试通过，运行状态不代表可发布。
- 主判定仅选择本轮最高序号的 `FINAL` + `TEST_RUN` 记录；草稿、已撤销及局部判定保留在判定历史中。
- 没有正式整轮判定时显示“等待质量判定”，不从完成状态或局部 PASS 推导可发布。
- 覆盖率为空时显示“未知”；查询尚无数据时计数显示破折号，避免与 0 混淆。
- 概览中的历史失败明确标为已记录的失败，可能早于最新判定。
- 证据展示采集来源、验证状态、原始内容与哈希；Agent 自述不替代正式证据。

## 验证边界与复查

浏览器验收通过 Playwright 驱动真实 Chromium 和本地 Next.js 生产服务。API 响应由隔离的、明确标记的合成验收数据提供，写请求被拦截；没有创建真实 Project / Run、调用 Agent 或执行 Runner。本次结果证明前端布局、交互和状态呈现，不证明一次真实测试周期通过，也不构成生产部署验收。

另外使用没有响应拦截的独立浏览器会话，只读打开既有本地 API 的项目、历史测试运行与 JUnit 证据。项目列表与历史 `RELEASE_BLOCKED` 判定正常显示，证据原文可读取。没有使用创建、执行、评估或状态变更操作；这是现有数据的前端连通性检查，不是重新执行测试。对应截图为 `real-run-desktop.png` 和 `real-evidence.png`，与合成场景分开保存。

本地预览使用 `http://127.0.0.1:3017`，正常浏览时调用既有本地 API；浏览器合成响应仅存在于独立验收会话。运行命令为 `npm --prefix web run start -- --hostname 127.0.0.1 --port 3017`，需先完成构建并保持 API 可用。

本地验收产物位于 `.impeccable/review/`，不纳入 Git：

- `setup.cjs`：只读合成 API 场景；通过 Playwright CLI `run-code --filename` 注册。
- `capture-final.cjs` / `capture-results.txt`：布局、状态与截图检查。
- `interaction-checks.cjs` / `interaction-results.txt`：真实表单、语言、焦点与刷新失败交互。
- `contrast-check.cjs` / `contrast-results.txt`：实际渲染的状态颜色与对比度。
- `finish-review.md` / `verdict-pass.md`：完整评审及针对修正项的复评。
- `desktop.png`、`mobile.png`、`tablet.png` 等：实际页面截图，内容为合成验收数据。

可复用规则由根目录 `DESIGN.md` 和 `.impeccable/design.json` 记录；产品事实与领域约束摘要见 `PRODUCT.md`，原始四份基础规范仍拥有最高规则权威。
