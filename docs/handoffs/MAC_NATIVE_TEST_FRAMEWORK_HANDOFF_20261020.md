## 1. 最新产品方向与本次工作的起点

- HyperTest 管理测试项目、下发测试任务、记录测试结论，并保留测试计划、用例、执行记录、原始证据和质量状态的追溯关系。
- Agent 负责测试分析、测试设计、测试实现与结果分析，调用 SUT 已有的测试框架和测试入口执行测试。
- 后续围绕真实 SUT 的原生测试工作流收敛，先实战再抽象；不要把自有 Runner 扩成可插拔 backend 矩阵，也不要先新写一套通用平台 Runner。
- 本地执行应能利用 Agent 所在电脑的实际代码、依赖、环境及现有测试入口。仅把推理放在本地，再强制所有测试到平台 Python/pytest 容器执行，不满足这次新方向。
- 跨会话顺序交接同一个测试任务是产品目标；它不等于并发多个 writer，也不等于接管其他聊天或伪造原生会话身份。
- 保留 Proposal、Verifier、Gate 以及不可变输入、原始事实和历史追溯；不要把 Agent 摘要、成功文案、文件 hash 或 shell 自述直接当成已验证执行事实。

当前实现的正式执行仍围绕 Python/pytest 与平台 Docker Runner；ADR-016 LOCAL 主要让本地 Agent 推理和实现、远端 Runner 测试。这是需要收敛的现状，不是新方向已经完成的证明。

上一轮的授权范围仅为白皮书 v1.4 的产品架构纠偏，以及本交接 Prompt。没有因该方向而修改执行代码、迁移数据库或发布生产。

## 5. 先选一条真实原生测试路径

从盘点到的 SUT 中选择一个实际可运行且有价值的现有测试入口，解释选择理由和明确范围。
优先复用已有测试框架、环境与报告，不先引入新的平台测试框架，不用新的 toy 应用或样例服务替代责任 SUT。
可先通过 Agent 原有工程工具验证项目测试入口；结果接入契约尚未实现时，保存待接入材料，不冒称已完成 HyperTest 新架构线上闭环。
在受控条件下执行真实的正向与负向路径，并保留原始退出码、日志、测试报告和运行上下文。
负向路径优先采用已有失败用例、可核对的历史缺陷版本或获准的隔离失败条件；不要破坏共享环境，也不要把人为制造的失败冒称产品缺陷。
如果暂时不能安全取得真实负向结果，保留这项验收缺口并说明所需条件，不编造通过或扩大结论。

每次运行至少记录以下可核对信息：

- SUT 仓库身份、完整提交、已有本地变更与实际使用的测试资产版本。
- 测试入口、工作目录、框架/工具版本、必要环境和明确的执行范围；命令记录须去除秘密值。
- 开始/结束时间、进程退出码、原始报告格式、各项结果与失败定位信息。
- 原始文件的保存位置、字节数和 hash，以及它们与该次执行的关联；hash 只证明完整性，不证明执行来源可信。
- 哪些结果是直接观察、哪些是 Agent 推断、哪些已由平台验证，以及尚不能形成正式质量结论的缺口。

## 6. 用真实结果决定最小协议与领域增量

基于上述真实测试流程，设计最小的“计划 → 用例 → 执行记录 → 证据 → 结论”链，并与既有 Requirement / Risk / Implementation / Finding / Verdict 对齐。
不要在没有实际需求时增加通用执行器、插件矩阵、队列体系、Graph DB 或新的 Agent Loop。
正式 ADR 至少写清：任务由谁领取，原生测试由谁调用，执行记录由谁提交，原始报告如何收集，Verifier 如何确认事实，Gate 如何据此形成结论。
区分本地探索输出、待验证执行材料和正式 Evidence；在新的信任规则落地并验收前，不把本地 shell 结果直接接入旧的可信 Runner 身份。
明确固定源码与本地未提交修改、环境版本、外部依赖和测试资产如何进入不可变输入及历史记录。
明确本地执行是否需要源码传输、实际上传哪些内容、保留在哪里；不得沿用旧上传流程就默认获得私有源码外发授权。

跨会话交接设计应记录原任务、已接受状态、剩余工作、原始证据、继任会话与显式接续动作，并隔离旧写入者。
不要把旧会话 ID 换个字符串当作续接，不回写历史身份，不把交接摘要当成原始事实，也不推导同一任务支持并发多 writer。
先提交可审阅的 ADR 与规范一致性修改，再按其边界实现最小接入；测试覆盖应围绕实际事实接受、历史保留与失败恢复，不照抄实现细节。

## 7. 安装、断线与副作用的边界

如需验证现有 MCP，按固定发行下载 wheel 和清单，校验大小、SHA-256、源码身份，再在独立环境安装；不要用移动 main 冒充固定发行。
管理密钥来自新机操作者安排的安全交付，使用本机私有文件或隐藏终端输入，不粘贴进聊天、命令参数、MCP 配置或仓库。
现有 setup / doctor、通用 stdio 提交读取和受控 Codex LOCAL 绑定是不同能力；安装成功不代表跨会话接力、原生框架接入或当前聊天已绑定。
任何写操作出现 UNKNOWN 或丢失响应时，保留原 journal、业务 key 和对象身份，先查询原操作；不自动重发 POST、换 key、创建替代任务或重复签发凭据。
没有安全对账入口时明确停止相关副作用并请求操作者处理，继续不依赖它的分析工作。

## 8. 新机凭据与生产保全

私有 glab 配置、SSH 私钥、Operator/device/integration key、CA 和 Provider 登录不会随 Git 迁移；不要复制旧 Mac 私有交接目录或认证文件来凑齐环境。

若新机没有经操作者配置并验证的 `ssh hypertest-one` 别名，停止远端操作，由操作者按 `docs/SERVER_OPERATIONS.md#ssh-access` 配置；不要猜测服务器地址或复用旧机私钥。
仅讨论或修改文档不隐含生产发布、数据库迁移、私有源码上传或新增问题单授权。
未来获准改生产时，保全既有数据、授权、VPN 白名单、服务器与本地 Connector 两种受管 Harness 模式，以及原 Runner 执行记录和历史结论。
新产品方向不能成为删除旧事实、重写旧 Verdict、放宽 Evidence 校验或绕过恢复流程的理由。
